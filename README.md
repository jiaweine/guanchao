## 产品是什么

观潮面向小红书、微博、抖音、B站等内容平台的账号与内容调查。用户不需要先选择算法或检测模式，只需要给出目标和现有资料；系统会自己决定下一步最值得检查什么，并把判断、证据、反向线索、稳定性和资料缺口留在同一任务里。

它不是“分类器 + 聊天框”。真正的产品单位是一个持续调查：资料可以补充，目标可以追问，执行过程可以复盘，人工复核可以进入后续校准和后训练数据。

客户页面只出现业务语言：**调查、账号、素材、判断、把握度、稳定性、证据、待补资料、人工复核**。内部模型、特征、权重、训练方法和工具名称不会出现在产品界面。

## 为什么是 Agent Harness

观潮自己的 Runtime 负责完整任务闭环：

```text
目标
 ↓
观察当前资料
 ↓
估计不确定性 / 信息价值 / 核查成本
 ↓
自主选择下一步工具
 ↓
执行真实核查
 ↓
验证输出
 ↓
稳定性探针 / 反向证据
 ↓
达到证据门槛后成案
 ↓
人工复核 → 回放校准 / 后训练语料
```

这里最重要的不是“能调用几个工具”，而是**什么时候调用哪个工具、什么时候继续找证据、什么时候停止、什么时候拒绝过早下结论**。

### 自研决策层

`OwnedPolicy` 不是固定工作流。每次决策都会根据当前状态重新计算下一步的预期价值，考虑：

- 当前判断的不确定性；
- 是否接近决策边界；
- 样本量与素材完整度；
- 多模态素材是否已经可读取；
- 是否存在同批账号可做相对对照；
- 当前证据是否单边；
- 用户是否要求谨慎、反向核查或避免误判；
- 稳定性是否足以支持结束任务；
- 每个工具的前置条件和信息增益。

因此，同一个目标在不同资料条件下不会机械走同一条步骤链。

### 稳定性探针

除了“当前分数是多少”，观潮还会检查结论是否被少数帖子主导。`stability.probe` 对近期内容执行 leave-one-out 反事实回放：逐条移除内容重新判断，观察最大摆动和整体离散度。如果删掉一两条内容就让结论大幅改变，最终把握度会被主动压低。

### 反向证据

对于低把握度、接近边界或用户明确要求谨慎的任务，Harness 会主动执行 `evidence.challenge`，寻找个人化经历、明确合作披露、非模板表达等可能推翻初始判断的证据，而不是只累积支持自己第一印象的线索。

## 多模态输入

一个调查可以同时加入：

- 账号主页和近期文本；
- 图片 / 截图；
- 视频；
- 音频；
- TXT、Markdown、CSV、JSON、日志；
- PDF / DOCX 等待企业自己的文档解析服务接入。

多模态感知与 Agent 决策严格分层：**外部或本地开源模型只负责“看见/听见什么”，不负责决定账号身份。** 感知结果会作为不可信观察进入观潮自己的证据层，再由自研策略、检测、稳定性与验证器决定下一步。

社媒内容、OCR 文本、字幕和文档里的任何“指令”都只被当作证据文本，不拥有改变 Agent 行为的权限。

### 可选开源感知

观潮核心不依赖外部大模型即可运行。需要更强多模态时，可以连接本地 OpenAI-compatible 视觉服务和 ASR 服务：

```bash
export GUANCHAO_VISION_ENDPOINT=http://127.0.0.1:8001/chat/completions
export GUANCHAO_VISION_MODEL=Qwen/Qwen3.5-27B
export GUANCHAO_ASR_ENDPOINT=http://127.0.0.1:8002/transcribe
```

视觉侧默认配置名称使用 Qwen3.5，可替换为团队部署的其他开源视觉模型；语音侧适合接 Qwen3-ASR 一类本地转写服务。模型只做事实提取，不进入 Harness 的控制权边界。

没有配置感知服务时，图片 / 视频 / 音频会诚实显示为“待读取”，不会伪造分析结果。文本类文档可直接在本地读取。

## 自研识别核心

当前识别层组合彼此独立、可回放的信号：

- 商业与价格表达的持续密度；
- 行动引导和转化压力；
- 联系方式、进群、店铺等导流；
- 跨内容重复转化句式；
- 内容结构与模板复用；
- 发布时间的批量化 / 固定节奏；
- 浏览、点赞、评论、分享之间的互动形态；
- 主页长期经营线索；
- 商业合作披露；
- 个人经历、利弊叙述和表达变化；
- 多模态素材中的可观察商业线索与身份一致性。

输出区分两个概念：

- **营销倾向**：是否表现为长期、系统性的商业内容运营方式；
- **隐性推广风险**：在商业倾向较高时，当前样本是否缺少足够清晰的披露。

商业内容本身不等同于违规，系统不会把“营销倾向”直接映射为处罚建议。

## 受控自进化与后训练

观潮不允许 Agent 在生产环境随意改源代码。学习发生在两个有回归门槛的层次。

### 1. 在线校准

人工复核会沉淀成可重放样本。`EvolutionEngine` 会生成候选校准，并执行：

- 5 折确定性回放；
- 平均指标提升门槛；
- 最差折退化门槛；
- 两类样本分别检查召回回归；
- 只有整体和类别稳定性都通过才接纳；
- 同时对 Harness 的谨慎阈值做有界调整。

这比只在一个留出集上“涨分就升级”更难被小样本偶然性欺骗。

### 2. Harness-aware 后训练数据

已完成的 Agent 轨迹 + 人工复核可以导出 JSONL：

```text
GET /api/post-training/export
```

每条记录包含任务目标、观察资料、执行轨迹、最终回答和人工标签，可继续用于企业自己的 SFT、偏好学习或策略后训练。Runtime 与训练器解耦，因此可以替换训练方案而不重写产品执行层。

## 可靠性与安全边界

- 同一个调查同时只允许一个执行任务，防止并发状态互相覆盖；
- 后台执行使用有界 worker pool，而不是无限创建线程；
- SQLite 使用 WAL、外键和必要索引；
- 单个上传默认限制 30 MB，可通过环境变量调整；
- 上传文件名会去除路径信息；
- 内部素材存储路径不会出现在客户 API 和执行记录中；
- 视频抽帧使用临时目录并在完成后自动清理；
- 无法解析的 PDF / DOCX 不会伪装成“已读取”；
- 工具结果必须先经过 `ResultVerifier` 才能进入后续状态；
- 出错时客户侧保留可理解的失败状态，不回显内部异常堆栈；
- 当前没有自动封禁、举报、处罚或下架工具。

## UI

界面按“调查工具”而不是“AI 展示页”设计：

- 低饱和暖中性色 + 单一墨绿色强调；
- 系统字体、固定字号层级；
- 分隔线和连续工作面替代卡片海；
- 标准按钮、标签页、表单和上传交互；
- 动效只表达执行、上传、状态切换和反馈；
- 支持 `prefers-reduced-motion`；
- 桌面端保持调查列表 / 工作区 / 判断证据三段结构；
- 小屏结构性折叠侧栏，判断区移动到任务下方；
- 客户页面不显示模型厂商名、算法名、权重或训练术语。

## API

| Method | Endpoint | Purpose |
| --- | --- | --- |
| `GET` | `/api/status` | 服务状态与输入能力 |
| `GET` | `/api/cases` | 调查列表 |
| `POST` | `/api/cases` | 创建调查 |
| `GET` | `/api/cases/{id}` | 获取任务、消息、素材和执行记录 |
| `POST` | `/api/cases/{id}/assets` | 上传图片 / 视频 / 音频 / 文档 |
| `POST` | `/api/cases/{id}/messages` | 提交目标并启动 Harness |
| `GET` | `/api/runs/{id}` | 获取执行状态、证据和判断 |
| `POST` | `/api/feedback` | 提交人工复核 |
| `POST` | `/api/evolution/run` | 运行受控多折回放与校准 |
| `GET` | `/api/post-training/export` | 导出后训练轨迹 JSONL |
| `POST` | `/api/demo` | 创建并运行内置示例 |

## 设计边界

观潮的目标不是宣称一个垂直项目“全面超过所有基础模型”，而是把通用模型通常不会替你解决的部分——**领域工具选择、证据门槛、反向核查、稳定性、持续状态、人工反馈和回归验证**——做成自己的产品能力，并在内容账号调查这个具体任务上不断用可测量结果提升。
