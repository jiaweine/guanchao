## 观潮解决什么问题

观潮面向需要持续研判社交账号的内容治理、品牌安全、舆情和运营团队。真正耗时的工作通常不是“算一个分数”，而是：

- 从主页、近期内容和素材里找出真正有区分度的证据；
- 在证据不一致时继续核查，而不是过早下结论；
- 把尚未人工确认的结果组织成待复核队列；
- 让人工复核准确对应到某一次具体调查结果；
- 把经过确认的轨迹沉淀成后续校准和后训练数据。

因此，观潮的产品单位不是一次分类，而是一个可以持续补资料、继续追问和重复复核的**调查任务**。

## 核心闭环

```text
创建调查
  ↓
加入账号资料 / 文本 / 图片 / 视频 / 音频 / 文档
  ↓
Agent 根据当前不确定性和信息价值选择下一步
  ↓
读取主页 / 扫描内容 / 对比模式 / 核对素材 / 反向挑战
  ↓
稳定性验证
  ↓
形成判断与证据链
  ↓
进入待复核队列
  ↓
人工确认：普通创作者 / 无法判断 / 营销运营
  ↓
复核绑定具体 run，进入校准与后训练数据
```

客户界面只使用业务语言：**调查、账号、素材、判断、把握度、稳定性、证据、待补资料、待复核、人工复核**。模型名称、内部特征、权重和训练细节不会出现在工作台里。

## 自主调查而不是固定脚本

`OwnedPolicy` 每一步都会重新判断哪项核查最值得做。它综合考虑：

- 当前判断的不确定性和是否接近决策边界；
- 样本量、主页资料和多模态素材是否完整；
- 当前证据是否过度单边；
- 是否存在同批账号可做对照；
- 用户是否明确要求谨慎、避免误判或寻找反证；
- 稳定性是否足以支持结束任务；
- 不同工具的前置条件、信息增益与成本。

所以，同一个目标在不同资料条件下不会机械走同一条步骤链。

### 稳定性探针

除了看当前判断，系统还会检查结论是否被少数帖子主导。稳定性探针通过移除单条内容重新计算，观察判断摆动。如果删掉一两条内容就会显著改变结果，最终把握度会被主动压低。

### 反向证据

当结论接近边界、把握度不足，或用户明确要求谨慎时，系统会主动寻找可能推翻第一印象的证据，例如更强的个人化叙述、非模板表达、明确商业披露和与当前结论冲突的素材。

## 多模态输入

一个调查可以同时包含：

- 账号主页与近期文本；
- 图片和截图；
- 视频；
- 音频；
- TXT、Markdown、CSV、JSON、日志；
- PDF、DOCX 等需要外部解析服务的文档。

多模态感知和 Agent 决策严格分层。外部或本地模型只负责提取可观察事实，不拥有调查控制权。图片文字、字幕、帖子正文和文档里的任何“指令”都只被当作证据文本，不能改变 Agent 行为。

没有配置视觉或语音感知服务时，相关素材会保持“待读取”，不会伪造分析结果。

## 人工复核是正式数据模型

复核不再只绑定整个 case，而是绑定某一次具体 `run_id`。同一次结果重复复核会更新原记录，而不是制造多个冲突标签。

支持三种人工结论：

- `confirm_ordinary`：确认更像普通创作者；
- `uncertain`：当前资料不足或存在争议；
- `confirm_marketing`：确认存在持续营销运营特征。

其中 `uncertain` 不会被强行转成二元训练标签。只有明确的人工确认才进入在线校准和后训练数据。

待复核队列默认只展示已经完成、但尚未人工确认的最新调查结果，让工作台可以从“单案 Demo”进入持续生产流程。

## 受控学习

人工确认会沉淀成可重放样本。`EvolutionEngine` 对候选校准执行多折回放、类别回归检查和最差折退化门槛，只有整体表现稳定提升时才接纳。

经过人工确认的调查轨迹可以导出：

```text
GET /api/post-training/export
```

每条记录绑定具体 `case_id` 与 `run_id`，包含目标、观察、执行轨迹、最终回答和人工结论。`uncertain` 记录不会进入二元训练集。

## 数据与安全边界

- 同一个调查同时只允许一个 Agent run；
- 后台执行使用有界 worker pool；
- SQLite 开启 WAL、外键和必要索引；
- 单个上传默认限制 30 MB；
- 空文件会被拒绝；
- 上传文件名会去除路径信息；
- 本地素材存储路径不会回传到客户 API；
- 数据库写入失败时会清理已落盘的临时素材；
- 删除调查会同时删除关联素材文件、消息、run 和复核记录；
- 核查运行中禁止删除调查或素材，避免状态竞争；
- 无法解析的文件不会伪装成“已读取”；
- 当前没有自动封禁、举报、处罚或下架工具。

商业内容本身不等同于违规，观潮只提供辅助研判和证据组织，不替代平台规则、合同事实或人工最终处置。

## 产品界面

界面按高频调查工具设计，而不是 AI 展示页：

- 默认左侧先展示**待复核**，可切换到全部调查；
- 中间保留持续对话、素材补充和执行状态；
- 右侧集中展示判断、稳定性、证据、素材和过程；
- 完成调查后提供三态人工复核，不逼迫用户做错误的二元选择；
- 使用低饱和中性色和单一强调色；
- 标准控件优先，动效只表达执行、上传和状态变化；
- 支持 `prefers-reduced-motion`；
- 小屏采用结构性折叠，而不是缩小桌面布局。

## 快速启动

```bash
git clone https://github.com/jiaweine/guanchao.git
cd guanchao

python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
make run
```

Windows PowerShell：

```powershell
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
make run
```

打开：

```text
http://127.0.0.1:8765
```

```bash
docker build -t guanchao .
docker run --rm -p 8765:8765 guanchao
```

## API

| Method | Endpoint | Purpose |
| --- | --- | --- |
| `GET` | `/api/status` | 服务状态、输入能力和复核指标 |
| `GET` | `/api/cases` | 全部调查 |
| `POST` | `/api/cases` | 创建调查 |
| `GET` | `/api/cases/{id}` | 获取任务、消息、素材、run 与复核 |
| `DELETE` | `/api/cases/{id}` | 删除调查及关联数据 |
| `POST` | `/api/cases/{id}/assets` | 上传多模态素材 |
| `DELETE` | `/api/cases/{id}/assets/{asset_id}` | 删除单份素材 |
| `POST` | `/api/cases/{id}/messages` | 提交目标并启动 Agent |
| `GET` | `/api/runs/{id}` | 获取执行状态、证据和判断 |
| `GET` | `/api/review-queue` | 获取待复核或已复核调查 |
| `POST` | `/api/reviews` | 对具体 run 提交或更新人工复核 |
| `POST` | `/api/evolution/run` | 执行受控回放与校准 |
| `GET` | `/api/post-training/export` | 导出经过人工确认的轨迹 JSONL |
| `POST` | `/api/demo` | 创建并运行内置示例 |
